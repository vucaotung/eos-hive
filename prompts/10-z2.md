# 10 · Pha 1 — Z2: kiểm thử, GitHub, SSH

**Mục tiêu:** chứng minh bản 0.0.0 xanh trên Z2, đưa lên GitHub (riêng tư), và có SSH không mật khẩu tới `vps169`, `vps173`.
**Chạy ở:** Z2 (nếu Claude Code chạy ở máy khác, bọc mọi lệnh bằng `ssh z2 '…'` và làm bước 0 để xác nhận).
**Đọc trước:** `00-MASTER.md`.

## Bước 0 — Hiện trạng (chỉ đọc)
```bash
hostname; whoami; lsb_release -ds; uname -r
docker --version; docker ps --format '{{.Names}}\t{{.Ports}}'
node -v; python3 -V; psql --version; git --version; gh --version
df -h ~ | tail -1; free -g | sed -n 2p
ss -ltn | grep -E ':(5433|3901)\b' || echo "cổng 5433/3901 trống"
git -C ~/src/eos-hive log --oneline | head -3 ; git -C ~/src/eos-hive tag
```
Báo: máy có đúng Z2 không (hostname dạng `vincent-HP-Z2-Mini-G4-Workstation`); thiếu gì.

## Bước 1 — Gói còn thiếu
- `sudo apt-get install -y postgresql-client python3-requests git curl xz-utils` (chỉ gói thiếu).
- Node **≥ 22** bắt buộc. Nếu thiếu: **hỏi người dùng** chọn `nvm` hay NodeSource, rồi cài. Không tự chọn.
- `gh`: nếu thiếu, hướng dẫn cài theo trang chính thức https://cli.github.com (hỏi trước).

## Bước 2 — Postgres 16 thử (Docker)
```bash
mkdir -p ~/.config/eos-hive && chmod 700 ~/.config/eos-hive
if [ ! -f ~/.config/eos-hive/pg.env ]; then
  PW=$(openssl rand -hex 16)
  docker run -d --name eos-pg --restart unless-stopped -e POSTGRES_PASSWORD="$PW" -p 127.0.0.1:5433:5432 postgres:16
  ( umask 077; echo "EOS_TEST_DSN=postgres://postgres:$PW@127.0.0.1:5433/eos_test" > ~/.config/eos-hive/pg.env )
  unset PW
fi
for i in $(seq 20); do docker exec eos-pg pg_isready -U postgres && break; sleep 2; done
```
Không in `pg.env`.

## Bước 3 — Kiểm thử
```bash
cd ~/src/eos-hive; set -a; . ~/.config/eos-hive/pg.env; set +a
make test-db           # kỳ vọng: "test_db: ĐẠT", 108 bảng, 5 view
make test-mcp          # kỳ vọng: "MCP e2e: 16 bước đạt"  (tự dựng lại CSDL thử từ đầu)
mkdir -p ~/.local/bin
curl -fsSL https://github.com/PostgREST/postgrest/releases/download/v12.2.3/postgrest-v12.2.3-linux-static-x64.tar.xz | tar -xJ -C ~/.local/bin
POSTGREST_BIN=~/.local/bin/postgrest make test-bridge    # kỳ vọng: "bridge: 7 bước đạt"
```
Mỗi bộ test tự dựng lại CSDL thử, chạy thứ tự nào cũng được.
Thất bại → xem `docs/05-xu-ly-su-co.md` mục D; sửa nguyên nhân; **không** nới kiểm thử.

## Bước 4 — Git
```bash
cd ~/src/eos-hive
git status --short | head           # kỳ vọng: sạch
git log --oneline | head -3; git tag    # kỳ vọng: commit khởi tạo + tag v0.0.0
make hooks && make secrets          # kỳ vọng: "check_secrets: sạch"
```
Nếu thư mục chưa là repo git: `git init -b main`, `make hooks`, `make secrets`, `git add -A`, commit `chore: khởi tạo Tổ Ong v0.0.0`, `git tag -a v0.0.0 -m "Tổ Ong 0.0.0"`.

## Bước 5 — GitHub (hỏi người dùng trước khi tạo)
1. `gh auth status`. Nếu lỗi: nói người dùng chạy `unset GH_TOKEN; gh auth login` (tương tác, họ tự làm).
2. Hỏi người dùng: "Tạo repo **riêng tư** `vucaotung/eos-hive` và đẩy `main` + `v0.0.0`?" Chỉ khi họ trả lời đồng ý: `scripts/publish_github.sh vucaotung/eos-hive` (script tự hỏi "yes"; bạn gõ `yes` thay họ **chỉ sau** khi họ đã đồng ý trong chat).
3. Kiểm tra: `gh repo view vucaotung/eos-hive --json visibility -q .visibility` → `PRIVATE`.
4. CI: `gh run list --limit 3`; chờ `gh run watch`. Nếu đỏ do môi trường CI (không do mã), sửa `.github/workflows/ci.yml` trên nhánh `fix/ci`, mở PR.

## Bước 6 — SSH tới hai VPS
1. `ls -l ~/.ssh/config ~/.ssh/*.pub 2>/dev/null`; `grep -E '^Host (vps169|vps173)' ~/.ssh/config`.
2. Thiếu bí danh: hỏi người dùng **user, cổng, tệp khóa** cho từng máy rồi ghi vào `~/.ssh/config`:
   ```
   Host vps169
     HostName 169.58.107.168
     User <user>
     IdentityFile ~/.ssh/<khóa>
     ServerAliveInterval 30
   Host vps173
     HostName 173.249.51.69
     User <user>
     IdentityFile ~/.ssh/<khóa>
     ServerAliveInterval 30
   ```
3. Chưa có khóa: hỏi người dùng có muốn tạo khóa mới (`ssh-keygen -t ed25519 -f ~/.ssh/eos_deploy -C eos-hive-deploy`, đề nghị đặt passphrase + `ssh-agent`). In **khóa công khai** (`cat ~/.ssh/eos_deploy.pub`) để họ tự dán vào `authorized_keys` trên VPS. Không in khóa riêng.
4. Kiểm tra: `ssh -o BatchMode=yes -o ConnectTimeout=8 vps169 'hostname; id -un; sudo -n true && echo sudo-ok'` (tương tự `vps173`).
   - Nếu hiện yêu cầu xác thực qua trình duyệt (Tailscale SSH): báo người dùng; cron/Claude Code không dùng được đường đó → cần khóa SSH riêng.
   - Cần quyền root hoặc sudo không mật khẩu. Nếu không có: dừng, hỏi.
5. Đưa **mật khẩu root từng bị dán vào chat** lên danh sách việc nhắc người dùng (chuyển sang khóa, tắt đăng nhập mật khẩu) — không thực hiện thay.
