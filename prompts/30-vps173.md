## Bước 2 — Tạo 4 profile agent (hỏi người dùng trước)
Hỏi người dùng 3 điều: (a) **model/provider** cho worker (hiện ops-admin dùng DeepSeek, team_admin dùng 9router); (b) cho phép tạo 4 profile (chưa tạo `eos-phap-che`: agent `phap-che` chưa định nghĩa, đang tắt) `eos-dieu-phoi`, `eos-van-thu`, `eos-nhan-su`, `eos-quan-tri-du-lieu`; (c) đồng ý **tắt terminal ghi hệ thống** cho cả bốn (chỉ dùng MCP enterprise-os; không Telegram/Zalo).
Cách tạo: `hermes profile --help` rồi `hermes profile create <tên>` (hoặc nhân bản profile trống nếu có). Sau đó cấu hình tối thiểu theo tài liệu Hermes: không gắn nền tảng chat, không terminal quyền root, không web trừ khi người dùng muốn, approval mode `manual`. Báo cáo cấu hình cuối cùng của từng profile (không in khóa API).

Cập nhật CSDL cho khớp (nếu người dùng đổi tên profile): `UPDATE agent.agents SET hermes_profile='…' WHERE code='…'` qua `ssh vps169 'sudo docker exec -i eos-postgres psql -U postgres -d eos …'`.

## Bước 3 — Kiểm chứng giả định trên board thử `eos-smoke`
**Chỉ dùng board `eos-smoke`.** Làm theo `docs/07` §2. Kỳ vọng và cách ghi:

1. `hermes kanban create --help` → khớp cờ A1? Ghi cờ nào khác/thiếu.
2. Tạo thẻ: `hermes kanban create "EOS smoke 1" --board eos-smoke --assignee eos-quan-tri-du-lieu --tenant TEST --idempotency-key smoke-1 --body "Gọi kanban_complete với summary 'Kiểm thử cầu nối: hoàn tất' ." --json` → chụp `create.json` (A2, A3). Board chưa có mà lệnh lỗi → tìm lệnh tạo board, ghi vào `docs/07` và `handle_outbox`.
3. Chạy lại **cùng** `--idempotency-key` → xác nhận không tạo thẻ đôi (A4).
4. Quan sát dispatcher nhận thẻ (≤ 2 phút; A15): `hermes kanban show <id> --board eos-smoke --json`, `hermes kanban list --board eos-smoke --json`. Chụp `show-*.json`, `list.json` ở các trạng thái: `ready/running`, `blocked` (tạo thẻ 2 bảo agent `kanban_block` với lý do cụ thể), `done` hoặc `review` (A5–A7, A14).
5. Thử `comment`, `unblock`, `archive` đúng thứ tự đối số (A8, A9).
6. Mọi lệnh có `--json`: ghi **tên khóa thật** của `status`, tóm tắt, `metadata`, lý do chặn, bình luận, `updated_at`.
7. Dọn: `archive` mọi thẻ thử.

Lưu mẫu JSON (đã lược nội dung nhạy cảm) vào `~/eos-fixtures/` trên VPS 173 và `scp` về Z2 `~/src/eos-hive/bridge/test/fixtures/`.

## Bước 5 — Cài plugin và cầu nối
1. Gói cần có: `ssh vps173 'sudo apt-get install -y python3-requests'` nếu thiếu.
2. Plugin: chép `bridge/hermes_plugin/eos_bridge` vào thư mục plugin đã xác định ở bước 1; bật cho 4 profile `eos-*` theo cách Hermes quy định (A12). Khởi động lại gateway **chỉ khi cần**, vào lúc không có phiên Telegram/Zalo đang chạy (hỏi người dùng); dùng cách Hermes khuyến nghị (graceful).
3. Bật lingering nếu chưa: `ssh vps173 'loginctl enable-linger "$(id -un)"'`.
4. JWT cầu nối (từ Z2, bí mật không qua tay bạn): `scripts/issue_bridge_token.sh vps169 vps173 90`. Kết quả chỉ in tên khóa và độ dài.
5. Dịch vụ:
   ```bash
   ssh vps173 'mkdir -p ~/.config/systemd/user && cp /opt/apps/enterprise-os/deploy/eos-kanban-bridge.service ~/.config/systemd/user/ && systemctl --user daemon-reload'
   ssh vps173 'python3 /opt/apps/enterprise-os/bridge/eos_kanban_bridge.py --once'   # đọc env từ .env? nếu không, dùng: set -a; . ~/.hermes/eos_bridge/.env; set +a
   ```
   `--once` không lỗi, outbox rỗng. Rồi `systemctl --user enable --now eos-kanban-bridge` và `journalctl --user -u eos-kanban-bridge -n 20`.
6. Từ VPS 173 kiểm tới VPS 169: dùng thông tin trong `.env` mà **không in**: `ssh vps173 'set -a; . ~/.hermes/eos_bridge/.env; set +a; curl -s -o /dev/null -w "%{http_code}\n" -X POST "$EOS_API/rpc/outbox_pull" -H "Authorization: Bearer $EOS_BRIDGE_TOKEN" -H "Content-Profile: agent" -H "Content-Type: application/json" -d "{\"p_limit\":1}"'` → `200`.

Cấu hình MCP client của từng profile theo tài liệu Hermes (`hermes mcp --help`, hoặc mục `mcp_servers` trong `config.yaml` của profile): `url: https://work.enterpriseos.bond/mcp`, header `Authorization: Bearer ${EOS_MCP_TOKEN}`. Kiểm cú pháp thật (A16) và nơi Hermes đọc `.env` của profile; ghi vào `docs/07`.
