
## Bước 4 — Thử lược đồ trên CSDL nháp rồi dựng CSDL thật
1. Cài client để chạy script: `ssh vps169 'sudo apt-get install -y postgresql-client'` (hỏi nếu apt đòi gỡ gói khác).
2. Thử trên CSDL nháp `eos_test` (nhớ chỉ chứa `_test`):
   ```bash
   ssh vps169 'cd /opt/apps/enterprise-os && EOS_TEST_DSN="postgres://postgres:$(sudo cat /etc/eos/pg_superuser)@127.0.0.1:5434/eos_test" scripts/test_db.sh | tail -3'
   ```
   Kỳ vọng `test_db: ĐẠT`. Sau đó: `docker exec eos-postgres psql -U postgres -c "DROP DATABASE eos_test"`.
   (Mật khẩu hiện trong danh sách tiến trình vài giây; chấp nhận được trên máy do một người quản trị. Nếu không, ghi biến vào tệp `600` rồi `source`.)
3. CSDL thật:
   ```bash
   ssh vps169 'cd /opt/apps/enterprise-os/db && sudo docker exec eos-postgres psql -U postgres -c "CREATE DATABASE eos"
   for f in 00_core 10_work 20_doc 30_hr 31_payroll_kpi 40_crm 45_kb 50_views 60_agent; do
     sudo docker exec -i eos-postgres psql -U postgres -X -q -v ON_ERROR_STOP=1 -d eos < $f.sql 2>&1 | grep -v NOTICE || { echo "LỖI ở $f"; break; }
   done'
   ```
   `CREATE DATABASE eos` thất bại vì đã tồn tại → **dừng, hỏi**.
4. Đếm: 108 bảng cơ sở, 5 view (câu lệnh ở `docs/03` §3.1). **Không chạy `test_agent.sql` trên `eos`.**

## Bước 5 — Vai trò đăng nhập (mật khẩu sinh tại chỗ, không in)
```bash
ssh vps169 'sudo bash -s' <<'REMOTE'
set -euo pipefail
umask 077
MCPPW=$(openssl rand -hex 24); APIPW=$(openssl rand -hex 24)
docker exec -i eos-postgres psql -U postgres -X -q -v ON_ERROR_STOP=1 -v mcppw="$MCPPW" -v apipw="$APIPW" -d eos <<'SQL'
CREATE ROLE eos_mcp LOGIN PASSWORD :'mcppw' IN ROLE mcp_svc;
CREATE ROLE authenticator LOGIN NOINHERIT PASSWORD :'apipw';
CREATE ROLE nobody_anon NOLOGIN;
GRANT agent_bridge, nobody_anon TO authenticator;
SQL
printf 'MCP_DB_PASSWORD=%s\nAPI_DB_PASSWORD=%s\n' "$MCPPW" "$APIPW" > /etc/eos/db_roles.env
chown root:eos /etc/eos/db_roles.env; chmod 640 /etc/eos/db_roles.env
REMOTE
```
Cổng: `\du` thấy 3 vai trò mới; `/etc/eos/db_roles.env` quyền 640 root:eos.

## Bước 6 — PostgREST
```bash
ssh vps169 'sudo bash -s' <<'REMOTE'
set -euo pipefail
cd /tmp && curl -fsSL -o pgrst.tar.xz https://github.com/PostgREST/postgrest/releases/download/v12.2.3/postgrest-v12.2.3-linux-static-x64.tar.xz
sha256sum pgrst.tar.xz          # ghi vào ops-log; đối chiếu với trang release
tar -xJf pgrst.tar.xz && install -m 755 postgrest /usr/local/bin/postgrest && rm -f pgrst.tar.xz postgrest
. /etc/eos/db_roles.env
umask 027
cat > /etc/eos/postgrest.conf <<CONF
db-uri = "postgres://authenticator:${API_DB_PASSWORD}@127.0.0.1:5434/eos"
db-schemas = "agent"
db-anon-role = "nobody_anon"
jwt-secret = "$(openssl rand -hex 32)"
server-host = "127.0.0.1"
server-port = 3000
CONF
chown root:eos /etc/eos/postgrest.conf; chmod 640 /etc/eos/postgrest.conf
cp /opt/apps/enterprise-os/deploy/postgrest-eos.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now postgrest-eos
sleep 3; systemctl is-active postgrest-eos
curl -s -o /dev/null -w "rpc không JWT: %{http_code}\n" -X POST http://127.0.0.1:3000/rpc/outbox_pull
REMOTE
```
Cổng: dịch vụ `active`; gọi không JWT trả **401**.

## Bước 7 — Node và MCP
**7a. Node.** `ssh vps169 'node -v'`. Nếu < 22: **hỏi người dùng** cách cài (NodeSource hay nvm cho user `eos`), không tự chọn.

**7b. Cài gói và tạo `.env`** (mật khẩu lấy từ tệp đã có, không in):
```bash
ssh vps169 'sudo -u eos bash -c "cd /opt/apps/enterprise-os/mcp && npm ci --omit=dev --silent"'
ssh vps169 'sudo bash -s' <<'REMOTE'
set -euo pipefail
. /etc/eos/db_roles.env
umask 077
E=/opt/apps/enterprise-os/mcp/.env
if [ ! -f $E ]; then
cat > $E <<ENV
DATABASE_URL=postgres://eos_mcp:${MCP_DB_PASSWORD}@127.0.0.1:5434/eos
PORT=8790
MCP_RATE_PER_MIN=120
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REFRESH_TOKEN=
ENV
fi
chown eos:eos $E; chmod 600 $E
cp /opt/apps/enterprise-os/deploy/eos-mcp.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now eos-mcp
sleep 2; systemctl is-active eos-mcp; curl -s 127.0.0.1:8790/healthz
REMOTE
```

**7c. DỪNG — người dùng điền Google.** Nói họ tự mở `/opt/apps/enterprise-os/mcp/.env` trên VPS 169 (nano) và điền `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` (refresh token phạm vi **drive** đầy đủ, của tài khoản agent Workspace). Bạn chỉ kiểm: `sudo awk -F= '/^GOOGLE_/{print $1, length($2)}' /opt/apps/enterprise-os/mcp/.env` (mỗi dòng độ dài > 0), rồi `sudo systemctl restart eos-mcp`. Chưa điền vẫn tiếp tục được; chỉ công cụ ghi Drive chưa chạy.

Cổng: `eos-mcp` active; `/healthz` → `{"ok":true}`; POST mã sai vào cổng 8790 → 401.

## Bước 8 — Caddy và DNS (hỏi người dùng)
1. Nếu `getent hosts work.enterpriseos.bond` rỗng: **dừng**, nhờ người dùng tạo bản ghi DNS `work` trên **Cloudflare** trỏ `169.58.107.168`. Hỏi: đặt **DNS only** hay **Proxied**? (Khuyến nghị DNS only cho `/api` giới hạn theo IP; nếu Proxied, hỏi lại phương án chặn `/api`.)
2. Sao lưu: `sudo cp -a /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak.$(date +%F-%H%M)`.
3. Thêm khối (nếu chưa có `work.enterpriseos.bond`; nếu đã có, **chỉ thêm hai khối `handle`**, không viết lại):
   ```
   work.enterpriseos.bond {
       @bridge_api {
           path /api/*
           remote_ip 173.249.51.69
       }
       handle @bridge_api {
           uri strip_prefix /api
           reverse_proxy 127.0.0.1:3000
       }
       handle /api/* {
           respond "Forbidden" 403
       }
       handle /mcp* {
           reverse_proxy 127.0.0.1:8790
       }
       handle {
           respond "Enterprise OS" 200
       }
   }
   ```
4. `sudo caddy validate --config /etc/caddy/Caddyfile` → hợp lệ mới `sudo systemctl reload caddy`.
5. Kiểm từ Z2: `curl -s -o /dev/null -w '%{http_code}' -X POST https://work.enterpriseos.bond/mcp -H 'Authorization: Bearer eos_sai'` → **401**; `curl -s -o /dev/null -w '%{http_code}' https://work.enterpriseos.bond/api/rpc/outbox_pull -X POST` → **403** (Z2 không phải IP VPS 173).
